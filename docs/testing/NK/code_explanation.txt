UC-05: GENERATE AI STUDY SCHEDULE
=================================
Files: backend/agent/NKStudyScheduleService.h/.cpp
       backend/schedule/NKScheduleRules.h/.cpp
- Accepts the authenticated student ID, saved study preferences, and tasks.
- Calls the team's existing Agent, which delegates to IAiClient (the future
  Gemini adapter) to propose a schedule.
- Supports weekly or single-day planning. In daily mode, availability is
  restricted to the selected weekday before asking the AI.
- Checks student identity, unknown task IDs, invalid times, conflicting
  blocks, study-hour constraints, breaks, deadline violations, and more.
- Saves an accepted plan through the team's IScheduleRepository interface.
- On rejected AI output or an AI exception, makes no intentional write.
- On successful production save, IScheduleRepository::replace must be atomic
  so a database failure cannot leave half a schedule.
- No real Gemini API key is stored in the code. A team-owned IAiClient
  implementation must call Gemini over the server-side API.

UC-06: MODIFY AI SCHEDULE
=========================
Files: backend/schedule/NKScheduleEditor.h/.cpp
       backend/schedule/NKScheduleRules.h/.cpp
- previewMove() changes a proposed StudyBlock in memory BEFORE acceptance;
  it validates the whole schedule and never saves a preview.
- moveAcceptedBlock() loads the logged-in student's accepted schedule,
  locates exactly one matching assignment and original time range, applies
  the requested new time/title, checks preferences/deadlines/collisions,
  and saves only if the full result is valid.
- A failed edit leaves the existing schedule untouched by this service.
- Requires server-side Supabase row-level/ownership checks in production.
- The editor is reusable when the chatbot suggests moving a study session.

UC-07: INTERACT WITH AI CHATBOT
===============================
Files: backend/chat/NKChatbotService.h/.cpp
- Accepts a student question, a server-provided list of THEIR assignments,
  THEIR saved schedule, and up to 10 previous messages.
- Calls an injected INKChatAIClient (to be connected to Gemini). The AI can
  answer questions about schedule and tasks, or suggest creating a task or
  moving a study block.
- ask() NEVER automatically creates or edits a task. It returns a suggested
  action to display to the student for explicit confirmation.
- applyConfirmedAction() validates and applies a confirmed task creation
  through INKChatTaskWriter or a move through NKScheduleEditor.
- The authenticated student ID overrides any student ID supplied by the AI.
- Rejects oversized/blank messages, foreign task references and malformed
  actions; catches AI/network errors without affecting saved schedules.
- INKChatAIClient receives a 9-second deadline. Actual Gemini HTTP requests
  MUST set a network timeout; this synchronous service alone cannot stop a
  provider that ignores the deadline. Performance NFR needs live testing.
- INKChatTaskWriter must be implemented using the team's authorized task
  backend. Do not let browser clients provide someone else's student ID.
- Store pending proposed actions server-side for a hardened deployment so
  an untrusted browser cannot replace an action before confirmation.

INTEGRATION GAPS TO COORDINATE WITH THE TEAM
============================================
1. Actual Gemini: Team must provide server-side IAiClient and
   INKChatAIClient implementations, with secure API keys / timeouts.
2. Real student data: IScheduleRepository and INKChatTaskWriter need Supabase
   implementations with ownership enforcement and atomic writes.
3. Frontend/API: Next.js routes and UI must invoke these C++ services via an
   agreed backend bridge or move business logic to the eventual Next.js stack.
   No frontend/API bridge has been included here.
4. Open AA pull request #4 currently uses ScheduledEvent and UTC timestamps,
   whereas main's Agent/Schedule use weekly StudyBlock/TimeRange. These are
   separate models. Do NOT assume data can be saved interchangeably; agree
   with Ahnaf on an adapter/data conversion and a single production schedule
   repository before attempting full integration. NK's modules add no
   conflicts with AA's NEW FILE NAMES, but backend/CMakeLists.txt must merge.
5. Estimated duration, automatic replanning after external task changes, and
   breaking down large assignments are listed among NK's functional
   requirements; the three use-case services provide integration points,
   but a production AI prompt/workflow for these subfeatures is not yet
   implemented by the team's existing Gemini adapter (still pending).
6. The 9-second chat deadline is a target, not proof of NFR-12 performance.
7. Ensure version-control and school submission rules permit AI assistance;
   review, understand, and test code before signing off on it.
